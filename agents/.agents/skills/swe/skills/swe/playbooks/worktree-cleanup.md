### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at a provider-managed workspace outside that guessed directory (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it, then suggests a bucket. Pass `--transcripts <directory>` only for explicitly scoped history, or provide an activity index exported from the active harness through `--activity <json-file>`. Without history, activity is unknown, never safe. Audit jj workspaces separately with jj when applicable.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar. Pick each subagent's reasoning level and fast or standard speed for the job, per the Subagents section.
4. Pause on irreversible loss. The auditor holds all ignored files, native Git locks, reflog-only commits and submodule entries. Inspect `git ls-files --others --ignored --exclude-standard`, `git worktree list --porcelain`, the worktree HEAD reflog and submodule state. Ignored files are not automatically disposable caches. A clean top-level diff does not prove submodule data is safe, and branch refs do not preserve commits reachable only through a worktree reflog. Resolve each reported preservation hold with the user before removal; never bypass a lock or remove leftovers recursively. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` means untracked files, not disposable files. Name them and obtain approval before removal. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. Per approved path, use `git worktree remove <path>`, then `git worktree prune`. Do not force removal or recursively delete leftovers without checking and approving their exact contents. Branch refs survive, but that does not preserve worktree-only reflog or submodule commits; the preservation checks in step 4 must pass first. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
